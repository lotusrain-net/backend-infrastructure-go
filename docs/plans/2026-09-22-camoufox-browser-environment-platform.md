## 0. 结论摘要

平台分三层，职责严格分离：

1. **控制面（本仓库，Go）**：多租户与 IAM、环境库、凭据保险库、代理池、设备（客户端）注册与调度、会话生命周期、审计与可观测。
2. **管理控制台（本仓库 `web/`，Next.js）**：管理员用于管理账号、指纹环境、代理、设备与会话。
3. **客户端节点（独立仓库，桌面程序 + Python/Camoufox）**：运行在用户本机 Windows / macOS arm64，负责在引擎层执行指纹伪装、加载页面、承载账号登录。

核心边界决策：**Camoufox 及其 Python/Playwright 运行时全部位于客户端节点，本仓库不引入任何 Python/Playwright 代码**，因此不违反 `AGENTS.md` 的既有禁令。服务端只通过**客户端主动建立的控制通道**下发环境、账号与会话指令。

关键约束（必须在后续实现阶段先解决）：

- Camoufox 官方**没有文档化的 `server` 子命令，也没有 `camoufox-connector` 连接器包**（仅有 "Remote server hosting" 能力描述）。节点控制协议需**自建**，不能依赖贴文中不存在的接口。
- Camoufox 构建系统**仅支持 Linux，官方明确 WSL 不可用**；当前开发机为 WSL2，因此双击端产物必须在**独立 Linux 构建机或 CI**上交叉编译。
- 客户端位于 NAT 之后，服务端**不能主动向其发起 HTTP**；控制面必须由客户端出站长连接承载（见 §6）。
- Camoufox 是 Firefox 分叉，**不具备 Chromium 风格 Client Hints**；目标站点若强依赖 UA-CH（如部分 OpenAI 流程）存在兼容缺口。

## 1. 术语与角色

| 术语 | 含义 |
|------|------|
| 租户 Tenant | 隔离单元。账号、环境、代理、设备、会话均归属某租户 |
| 平台管理员 | 跨租户运维，管理租户、配额、全局代理与系统健康 |
| 租户管理员 | 管理本租户的账号库、指纹环境、代理、设备与成员 |
| 操作员 Operator | 仅可发起/释放会话，不能查看凭据明文 |
| 客户端 Device / Node | 用户本机的 Camoufox 桌面程序实例，是执行主体（以用户账号登录，非独立认证主体） |
| 客户端记录 Device Record | 控制面登记的客户端元数据（OS/版本/机器标识），归属某用户，用于在线状态与遥测 |
| 用户账号 User Account | 用户自助注册的服务端账号，同时用于登录控制台与客户端 |
| 环境 Environment / Profile | `OS 目标 + UA + 完整指纹 + 代理解析策略 + 账号绑定` 的强绑定单元 |
| 环境版本 Environment Revision | 环境配置的不可变快照，发布前需通过自洽校验 |
| 凭据 Credential | 目标站点账号密码（加密存储于保险库） |
| 代理 Proxy | 出口 IP 资源，含协议、认证、地理与风控标签 |
| 会话 Session | 一次「设备 ↔ 环境 ↔ 代理 ↔ 凭据」的租用，有生命周期与独占性 |

## 2. 需求（源自确认结论）

1. **多租户**：管理员管理账号与指纹，向客户端下发；租户间强隔离。
2. **用户自助注册**：用户在服务端用户界面自行注册并登录；客户端以同一用户账号认证。**取消管理员签发一次性注册码的流程**。
3. **下发内容**：环境（UA + 完整指纹 + 代理）+ 账号密码。
4. **运行位置**：Camoufox 运行在用户本机 macOS / Windows 客户端；Go 服务端仅下发控制。
5. **目标平台**：Windows + macOS arm64（放弃 Intel Mac）。
6. **代理池与质量管控**：含存活、属地真实性、风控标签检测与会话绑定。
7. **加密凭据库**：平台内加密存储，按会话下发。
8. **指纹粒度**：整套指纹与出口 IP 强绑定，并做逻辑自洽校验。
9. **前端**：复用现有 Next.js 做管理控制台。
10. **环境分配**：由**服务端自动分配可用环境**，管理员不逐台指派。
11. **会话触发**：**用户手动发起**，本期不做定时批量自动开。
12. **账号占用**：账号**独占**——同一目标站点账号同一时刻仅归一个环境/会话。

## 4. 组件职责

### 4.1 控制面（本仓库）

复用现有能力并新增领域模块：

- **复用**：`internal/modules/iam`（认证/RBAC）、`internal/modules/audit`、`internal/modules/task` + Asynq（`internal/platform/queue`、`scheduler`）、`internal/platform/database`、`httpserver`、`observability`。
- **新增领域模块（领域包保持无适配器依赖）**：
  - `tenant`：租户、配额、成员角色。
  - `environment`：环境模板、版本、发布自洽校验。
  - `credential`：凭据保险库（加密、轮换、授权）。
  - `proxy`：代理资源、健康与风控标签、绑定与归还。
  - `device`：客户端记录、登录会话、心跳、能力上报、命令队列。
  - `session`：会话编排（原子分配 环境×代理×凭据×设备）、生命周期、回收。
- **新增平台适配器**：`internal/platform/kms`（信封加密主密钥，可用环境密钥或外部 KMS 抽象）、`internal/platform/controlchannel`（长连接/WS 网关）。

### 4.2 客户端节点（独立交付物，不在本仓库）

- **桌面壳**：承载配置 UI、托盘、自动更新。
- **Node Agent（Python）**：启动 Camoufox（Playwright 兼容接口），加载服务端下发的指纹配置，向控制面上报心跳与遥测，接收并执行命令。
- **Camoufox 运行时**：指纹在引擎层注入；按代理推导 geo/时区/语言；本机 profile 目录加密。
- **交付与构建**：在 Linux 构建机/CI 上用 `multibuild.py --target windows macos --arch x86_64 arm64` 交叉编译；节点侧 Python 运行时打包进安装包；提供签名自动更新通道。
- 本仓库仅定义**接口契约**（OpenAPI + 命令信封），不承载节点代码。

### 4.3 管理控制台（本仓库 `web/`）

- 新增 pages：环境管理、账号库、代理池、设备与节点、会话监控、租户与成员；复用现有任务、审计、IAM 页面与 enterprise/cyberpunk 双主题。

## 6. 控制通道与下发协议

### 6.1 连接方向（关键约束）

客户端在 NAT 之后，**连接必须由客户端出站发起**。已确认采用：

- **WebSocket 长连**：客户端 `wss://.../api/v1/nodes/connect`，携带**用户访问令牌**（客户端以用户账号登录取得）；服务端在其上推送命令帧。心跳用于维持连接与在线判定，断线后客户端指数退避重连并补齐未确认命令。

不实现长轮询降级。命令帧保持 HTTP/JSON 语义，符合"服务端用 HTTP 命令下发控制"的意图，但不要求服务端主动连客户端。

### 6.2 命令信封

```json
{
  "id": "cmd_...",
  "type": "provision_session",
  "session_id": "ses_...",
  "issued_at": "2026-09-22T10:00:00Z",
  "expires_at": "2026-09-22T10:02:00Z",
  "nonce": "base64",
  "payload": { },
  "signature": "ed25519:..."
}
```

命令类型（首期）：

- `provision_session`：下发环境配置 + 短期凭据令牌 + 代理参数，启动 Camoufox。
- `stop_session` / `revoke_session`：停止并清理 profile。
- `rotate_fingerprint` / `rotate_proxy`：会话内轮换。
- `update_agent`：触发签名更新。
- `collect_logs` / `probe`：诊断。

### 6.3 安全属性

- 身份：客户端以**用户账号**登录取得访问令牌，长连走 WSS；设备不再是独立认证主体，不签发设备密钥对。
- 防重放：`nonce` + `expires_at`（短 TTL）+ 服务端单调计数。
- 传输：全程 HTTPS/WSS；生产强制 `COOKIE_SECURE=true` 与受信代理 CIDR。

### 6.4 配置与凭据交付

- **配置下载**：`GET /api/v1/nodes/environments/{revisionID}/config`，返回服务端生成的完整指纹配置（服务端是唯一真值源，节点只应用）。
- **凭据交付**：已确认采用**短期令牌取件**。控制面签发一次性、短 TTL 的凭据取件令牌，节点凭令牌取回并仅驻留内存，注入登录流程后即弃；不下发明文落盘，不采用设备公钥信封加密模式。
- 明文凭据**禁止**进入日志、遥测、审计 payload。

## 7. 用户账号与客户端认证

已确认：用户**在服务端用户界面自助注册并登录**，随后在专属浏览器客户端直接操作。**不采用**管理员签发一次性注册码的流程。

- **用户主体**：自注册用户即控制台与客户端的统一身份（`principal_type=user`）；同一账号既能登录管理控制台，也能登录专属浏览器客户端。
- **客户端认证**：客户端用**同一用户账号登录**并取得访问令牌，凭该令牌建立 WebSocket 长连、下载配置、发起会话。不再有独立的"设备账户"注册环节。
- **设备只是记录，不是认证主体**：客户端登录时上报设备信息（OS、arch、agent 版本、机器标识），控制面登记为 `devices` 行并归属该用户，仅用于在线状态、遥测与生命周期管理，不单独签发密钥。
- **站点凭据与用户身份分离**：客户端只是取回目标站点账号的通道；站点凭据按会话最小权限、短期令牌下发（§6.4），与用户自身账号无关。
- **吊销**：禁用用户即同时吊销其客户端访问；用户可在控制台查看并注销自己的在线客户端。
- **选择与确认流程**：用户登录后在客户端下拉中选择具体配置，**选择到确认使用的完整交互流程仍需专项设计（见 §9.1，标为待定）**；在流程定稿前，不得假定"点一下下拉即自动完成全部环节"。

## 8. 指纹与环境自洽

### 8.1 环境 = 强绑定单元

一个环境固定绑定：`目标 OS + UA + 完整指纹 + 代理地理策略 + 凭据`。服务端生成指纹配置时，须保证：

- `UA` 与 `target_os`、屏幕、字体、平台一致；
- **时区 / 语言 / 地理位置由代理出口地理推导**（Camoufox 支持按代理计算 geo/timezone/locale）；
- WebGL 渲染器字符串与 OS 匹配；
- Canvas/音频噪声种子随环境版本固定，保证会话内稳定、跨会话可轮换。

### 8.2 配置生成策略

- 由控制面调用 BrowserForge 兼容的生成逻辑（Go 侧实现或离线生成后存 `environment_revisions.config_json`），并以 `fingerprint_seed` 保证可复现。
- 节点侧**不做**随机补全，避免服务端与节点生成不一致；未显式配置的字段由服务端在发布时填满。

### 8.3 发布前自洽校验（checklist）

环境版本发布必须通过校验器，拒绝发布矛盾组合，例如：UA 声明 macOS 而字体为 Windows、时区与代理地理不符、WebGL 与 OS 冲突、屏幕尺寸超出 BrowserForge 分布。校验结果写入 `validated_at`。

### 8.4 兼容缺口（需重点评估）

- **无 Chromium Client Hints**：Camoufox 为 Firefox 分叉，无法注入 UA-CH。对隐式依赖 UA-CH 的平台（如部分 OpenAI / Cloudflare 流程）需专项验证，必要时在环境能力中标注"不适用"。
- **TLS/JA3**：TLS 指纹由 Firefox 网络栈决定，无法像 Chromium 反检测浏览器那样任意定制；作为已知风险登记。

## 9. 会话生命周期

```text
requested → provisioning → active → releasing → released
                     └──────── failed / expired ────────┘
```

1. **用户发起**：用户在专属浏览器客户端下拉选择配置（本人在客户端已登录）→ 经 WebSocket 长连到达控制面。**选择与确认的完整交互流程待定，见 §9.1。**
2. **自动分配**：控制面**自动挑一个可用环境实例**（环境版本 + 其独占账号 + 可用出口 IP），在单事务内一并锁定，避免指纹/账号/IP 错配。账号为独占资源，被占用时该环境**不出现在可用列表中**（见 §9.1）；分配时二次校验，抢占用户需重选。
3. **下发**：创建 `session` 与 `provision_session` 命令 → 经 WebSocket 到达客户端 → 客户端启动 Camoufox。**从"用户确认"到"浏览器就绪"之间是否需要进度反馈与取消，见 §9.1。**
4. **激活**：客户端回执 + 心跳，会话转 `active`，代理与账号进入独占状态。
5. **释放**：用户关闭或 TTL 到期 → `stop_session` → 代理归还并冷却、账号授权撤销。
6. **回收兜底**：Asynq 定时任务 `session.reap` 处理超时/失联会话。

**独占性**：同一 `proxy` 与同一 `credential` 在同一时刻至多被一个活动会话占用。

### 9.1 环境选择与确认流程（部分定稿，其余待定）

> 状态：**待定（TBD）**。第 3 项已定稿（见下），其余仍在设计中。任何"用户点下拉即自动完成"的说法都不成立，流程必须显式设计并确认。

**核心判断**：从"用户看到配置清单"到"浏览器真正就绪"之间存在多个需要用户决策或系统反馈的节点，不能默认一步到位。至少需要明确：

1. **选择粒度与呈现**：下拉列的"具体配置"展示哪些字段（地区、目标 OS、设备类型、账号所属站点）？是否需要分组/搜索/收藏？
2. **是否二次确认**：用户选中后，是立即开始分配，还是先展示一个确认面板（拟用账号、代理地区、预计时长/配额消耗），由用户点击"开始"？若需确认，确认面板要展示什么、是否提示将占用独占账号与 IP。
3. **账号/环境不可用时的交互（已定稿）**：**不做置灰、不做排队**。服务端在返回可用环境列表时，**直接把当前被占用（账号或代理不可用）的环境过滤掉**，响应中根本不出现；前端只渲染服务端返回的可用环境，无需自行判断。当过滤后列表为空时，前端显示**"无可用环境"**空状态。占用状态以服务端查询时点为准（见 §12 `GET /api/v1/nodes/environments/available`）。
4. **分配与就绪的过程反馈**：服务端分配到客户端启动浏览器之间需要时间，是否需要进度态（分配中 → 下配置 → 启动中 → 就绪）？是否允许**取消**分配？取消后账号/IP 如何归还。
5. **失败与重试**：分配失败、下发失败、启动失败各自的错误呈现与重试策略；是否需要自动换一个环境实例。
6. **会话信息可见性**：会话生效后，用户在客户端能看到什么（当前环境名、代理地区、剩余时长、账号所属站点脱敏标识），以及"结束会话"入口。
7. **多会话并行**：同一用户是否允许同时在多台客户端 / 多个窗口开启多个会话？是否受配额与独占资源限制。
8. **幂等与防重复点击**：用户连点"开始"时的去重；断线重连后会话状态的恢复。

**待确认的交互取向（进入设计时需拍板）**：

- A. **一键即用**：选中即分配，无确认面板，过程用进度条反馈，失败自动提示。
- B. **选择 → 确认面板 → 开始**：多一步确认，明确展示将占用的账号/代理与配额消耗。
- C. **选择 → 分配预览 → 用户确认 → 开始**：服务端先做一次"预分配"（不锁定），展示具体将使用的账号与 IP 地区，用户确认后才正式锁定。

> 上述取向会直接影响 API 设计（是否需要"预分配/确认"两个接口）、`sessions` 状态机（是否需要 `pending_confirmation` 态）、以及前端与客户端的交互形态。**在 §17 中登记为开放问题，待你确认后再定稿。**

**已定稿的不变量（与 3 相关）**：

- 可用环境列表**只包含当前可分配项**；被占用项在服务端被过滤，不进入响应、不在前端展示，也不提供"排队等待"入口。
- 空列表即**"无可用环境"**，是预期内的正常状态，不是错误。
- 由于服务端过滤与服务端分配之间存在时点差（用户可能选到刚被别人占用的环境），**分配环节仍必须做二次校验**，被抢占时返回明确错误让用户重新选择（该错误呈现方式并入第 5 项设计）。

## 10. 代理池与质量管控

- **来源**：HTTP/HTTPS/SOCKS5，住宅/移动优先；数据中心 IP 标注高风险。
- **体检 Worker（Asynq 周期任务）**：`proxy.healthcheck` 检测存活、延迟、真实出口 IP、属地真实性（与登记 geo 比对）、基础风控标签（是否被常见风控拦截页命中）。
- **状态机**：`available → leased → cooldown → available`；连续失败多次进入 `quarantine`。
- **绑定**：出口 IP 与指纹地理强绑定；会话内 IP 不得变更（除非显式 `rotate_proxy`）。
- **泄露防护**：要求节点在引擎层强制经代理解析 DNS，并由 Camoufox 能力控制 WebRTC 泄露。

## 11. 多租户与现有 IAM 的衔接

- 现有 `users/roles/permissions` 增加 `tenant_id`；引入角色：平台管理员、租户管理员、操作员、只读。
- 所有仓储查询强制带 `tenant_id` 过滤（在领域服务层做租户边界，避免越权）。
- **自注册用户的租户归属（已确认）**：**邀请制**——管理员生成邀请码/邀请链接，用户凭邀请注册并加入指定租户；无邀请不可注册。
- **客户端与用户共用认证基础设施**，不再有独立的"设备主体"；授权按租户与角色划分，客户端能力受用户角色约束。
- 迁移：新增列允许为空 → 回填默认租户 → 加非空约束与索引（分步 migration，兼容既有数据）。
- 前端路由与 API 均需携带租户上下文；RBAC 判定加入租户维度。

## 12. API 契约（`/api/v1` 扩展，仅设计）

**控制台/管理面**（操作员/管理员，JWT + RBAC）：

- `GET/POST /api/v1/environments`、`GET/PATCH /api/v1/environments/{id}`
- `POST /api/v1/environments/{id}/revisions`（发布，返回自洽校验结果）
- `GET/POST /api/v1/credentials`、`POST /api/v1/credentials/{id}/rotate`
- `GET/POST /api/v1/proxies`、`POST /api/v1/proxies/{id}/check`
- `GET /api/v1/devices`、`DELETE /api/v1/devices/{id}`（设备仅作为记录，无注册码签发）
- `GET/POST /api/v1/sessions`、`POST /api/v1/sessions/{id}/release`
- `GET /api/v1/tenants`、`GET/POST /api/v1/tenants/{id}/members`、`POST /api/v1/tenants/{id}/invitations`（生成邀请码/链接）
- `POST /api/v1/auth/register`（凭邀请码注册并加入指定租户）

**节点面**（**用户账号令牌认证**，不再有设备身份）：

- `WS /api/v1/nodes/connect`（命令通道，携带用户访问令牌）
- `GET /api/v1/nodes/environments/available`（列出该用户可见且**当前可分配**的具体配置清单，供客户端下拉；**被占用的环境由服务端过滤，不返回**；空结果 = 无可用环境）
- `GET /api/v1/nodes/environments/{revisionID}/config`
- `POST /api/v1/nodes/sessions`（用户发起会话，服务端自动分配环境）
- `POST /api/v1/nodes/credentials/{sessionID}/claim`（短期令牌取件）
- `POST /api/v1/nodes/heartbeat`、`POST /api/v1/nodes/commands/{id}/ack`

所有新增端点需同步进 `api/openapi.yaml` 并在实现阶段补齐契约测试。

## 14. 安全模型

- **身份**：控制台用户 JWT；客户端以**同一用户账号**登录取得短期访问令牌，长连走 WSS。
- **指令完整性**：命令签名 + 短 TTL + nonce；客户端验签后执行。
- **凭据保护**：信封加密（AES-256-GCM，AAD 绑定 tenant/environment/session），主密钥抽象为 `kms` 适配器（本地密钥或外部 KMS）；最小权限、按会话授权、用后即焚。
- **审计**：复用 `audit` 模块，覆盖环境发布、凭据取用、代理分配、会话下发/释放、客户端登录/注销；**审计不含凭据明文**。
- **供应链**：Camoufox/MPL-2.0 合规与 NOTICE 维护；节点安装包与更新二进制签名校验。
- **合规**：本平台为多账号指纹环境管理，属双用途技术，须在授权场景使用；设计上保留审计与最小权限以支持合规要求。

## 17. 风险与开放问题

| 风险 | 影响 | 应对 |
|------|------|------|
| Camoufox 无文档化 server/connector | 需自建节点协议，工作量与稳定性风险 | 控制面自定义命令信封 + 长连接；不依赖贴文接口 |
| 构建仅限 Linux，WSL 不可用 | 当前 WSL2 开发机无法出双端产物 | 独立 Linux 构建机 / CI |
| macOS x86_64 收缩 | Intel Mac 用户不可用 | 本期仅 arm64（已确认） |
| 无 Chromium Client Hints | 部分站点流程不兼容 | 环境能力标注 + 专项验证 |
| TLS/JA3 由 Firefox 栈决定 | 网络层指纹可被关联 | 登记为已知风险，评估代理侧 TLS 方案 |
| 多租户改造 IAM 表 | 迁移与越权风险 | 分步迁移 + 领域层强制租户过滤 + 越权测试 |
| 凭据泄露面 | 高敏感 | 信封加密、短期取件、内存驻留、审计脱敏 |
| 选择与确认流程未定 | 直接影响 API 与状态机，晚定会返工 | 见 §9.1，先拍板交互取向 A/B/C |

**已确认决策（2026-09-22）**：

1. 控制通道：**WebSocket 长连**（客户端出站建立），不实现长轮询降级。
2. 指纹生成：**控制面 Go 侧**为唯一真值源，节点只应用配置。
3. 凭据交付：**短期令牌取件**——节点凭一次性短 TTL 令牌取回凭据，仅驻留内存，用后即弃。
4. 开放 API：**本期不做**，仅控制台 + 节点面。
5. 用户准入：**用户自助注册并登录**，客户端以同一用户账号认证；**取消**管理员签发一次性注册码流程。
6. 环境分配：**服务端自动分配可用环境**，管理员不逐台指派。
7. 会话触发：**用户手动发起**（非定时批量）。
8. 账号占用：**账号独占**，一个目标站点账号同一时刻仅归一个环境/会话。
9. 用户准入方式：**邀请制注册**——管理员生成邀请码/邀请链接，用户凭邀请注册并加入指定租户。
10. 客户端下拉：**列出管理员发布的具体"配置/环境"清单**，用户选中后由服务端自动配齐该环境对应的独占账号与代理。
11. **不可用环境处理（已定稿）**：不做置灰、不做排队；服务端在可用环境列表中**直接过滤掉被占用的环境**，前端只渲染返回值，空列表显示"无可用环境"。
12. 身份模型：**用户账号是唯一身份**，同时用于控制台与客户端；客户端只是"这台机器"的记录，非独立账号。
13. 站点账号归属：**平台管理员录入并独占绑定环境**，用户不接触账号密码与代理参数；用户对平台账号（自助注册）与站点账号（无感使用）是两层不同概念。

**待定事项（TBD，需专项设计后再定稿）**：

1. **环境选择与确认流程**（见 §9.1）：第 3 项（不可用环境处理）已定稿；**仍待定**——选择是否二次确认、分配进度反馈、失败/取消如何呈现，以及对应的 API 与 `sessions` 状态机是否需要 `pending_confirmation`。**在定稿前，不得假定"点下拉即自动完成"。**
2. 同一用户**多会话并行**的配额与独占约束（§9.1 第 7 项）。
