# 浏览器环境平台（Undetectable 方案）— 总体设计

- 状态：设计草案（仅总体设计，不含实现）
- 日期：2026-09-22
- 关联仓库：本仓库承载 Go 控制面与管理控制台；用户机**节点代理（Node Agent）为独立 Go 仓库**，厂商浏览器为**商业闭源软件**
- 指纹引擎：**Undetectable Fingerprint Browser**（Chromium 内核，商业授权，本地 REST API + CDP）
- 取代：`2026-09-22-camoufox-browser-environment-platform.md`（Camoufox 方案，已废弃，见 §19 变更历史）

## 0. 结论摘要

平台分三层，职责严格分离：

1. **控制面（本仓库，Go）**：IAM、环境库、凭据保险库、代理池、客户端记录与调度、会话生命周期、审计与可观测。**首版为单租户**，多租户仅作预留（见 §11）。
2. **管理控制台（本仓库 `web/`，Next.js）**：管理员管理账号、环境、代理、席位与设备；用户凭邀请注册、登录、发起会话。
3. **节点代理（独立 Go 仓库，不在本仓库）**：运行在用户本机 Windows / macOS arm64，是**唯一能访问厂商本地 API 的进程**，也是平台唯一的**外部执行适配器**；把控制面指令翻译为 Undetectable 的 profile 操作与浏览器动作，驱动 Chromium 内核执行指纹与页面加载。其作用与边界见 §4.2。

核心边界：**本仓库不引入任何浏览器自动化运行时**；厂商浏览器与节点代理均为外部交付物。服务端通过**客户端主动建立的 WebSocket 长连**下发环境、账号与会话指令，数据面（页面流量）经代理直连出站。

**首版范围（本次明确，两项关键收敛）**：

1. **首版单租户；多租户只预留**。不交付租户管理界面、跨租户配额、租户维度 RBAC 与租户选择；但数据模型、领域接口与请求上下文**按多租户形态留好字段、接口和关键注释**，运行期固定落在唯一"默认租户"。详见 §11。
2. **节点代理是独立 Go 仓库，不在本仓库，且运行在用户自己的机器上**。它由**公司内部分发**（非公开商店）：用户经管理控制台"下载客户端"入口拿到安装包 → 安装为**用户级常驻托盘程序** → 用同一账号登录 → 设备登记 → 就绪。本仓库只交付其**接口契约**（节点面 OpenAPI、命令信封、配置下载 schema）、**下载入口与版本元数据 API**及兼容性约定，不含其源码与安装包本体；两侧仅通过对版本化的 HTTP/WS 契约耦合。详见 §4.2。

**与 Camoufox 方案的关键差异**：

- 厂商为 **Chromium 内核** → 原生支持 Client Hints，消除上一版最大的兼容缺口。
- 厂商直接提供 **Windows / macOS arm64** 安装包 → **不再需要 Linux 构建机与交叉编译**。
- 暴露**真实 CDP** → 节点代理可用 **Go（chromedp）**直连，**无需 Python**，`AGENTS.md` 禁令不被触碰。
- 指纹不再是自研生成，改为**厂商「配置(configid)」+ 有限覆盖** → 指纹可控度下降，需正面处理。
- 引入**商业授权与席位成本**、**本地 API 无鉴权**、**内核/配置漂移**等新风险。

## 1. 术语与角色

| 术语 | 含义 |
|------|------|
| 租户 Tenant | 隔离维度。首版只有唯一的"默认租户"；数据模型与接口按多租户形态预留，但不交付租户管理能力 |
| 平台管理员 | 跨环境运维，管理租户（预留）、配额、全局代理与席位 |
| 租户管理员 | 管理本租户的环境、账号库、代理、邀请与成员；首版等价于平台管理员 |
| 用户 User | 凭邀请注册的终端用户，是**唯一身份主体**（控制台与客户端同一账号） |
| 节点代理 Node Agent | **独立 Go 仓库**交付的独立程序，装在用户机，是平台唯一的外部执行适配器，驱动厂商浏览器（作用与边界见 §4.2） |
| 环境 Environment | `厂商配置(configid) + 覆盖(overrides) + 代理策略 + 账号绑定` 的强绑定单元 |
| 厂商配置 Vendor Config | Undetectable 提供的指纹配置，含 UA/屏幕/WebGL/字体/navigator 等成套数据 |
| Profile | 厂商浏览器的用户配置实例（指纹+代理+cookie 的载体），**每会话临时新建** |
| 凭据 Credential | 目标站点账号密码（加密存于保险库），**运行时注入，不落盘** |
| 代理 Proxy | 出口 IP 资源，含协议、认证、地理与风控标签 |
| 会话 Session | 一次「用户机 ↔ 环境 ↔ 代理 ↔ 账号」的租用，有生命周期与独占性 |
| 席位 Seat | 该用户机上 Undetectable 的付费授权；一人一席，公司统一采购 |

## 2. 需求（已确认）

1. **隔离范围**：**首版单租户**——管理员管理环境与账号并下发给客户端，不做租户间隔离的交付形态。多租户仅作为**预留能力**：数据模型、领域/仓储接口与请求上下文留好维度与注释（§11），运行期固定为默认租户。
2. **用户自助注册（邀请制）**：管理员生成邀请码/邀请链接，用户凭邀请注册；无邀请不可注册。首版邀请固定归属默认租户，不暴露租户选择。
3. **单一身份**：用户账号同时用于控制台与客户端；客户端只是"这台机器"的记录，非独立账号。
4. **客户端下拉选具体配置**：管理员发布具体环境清单，用户选中后服务端自动配齐该环境的**独占账号 + 指纹配置 + 代理**。
5. **指纹粒度**：环境 = 厂商配置 + 覆盖 + 代理强绑定，做逻辑自洽校验。
6. **代理池与质量管控**：存活、属地真实性、风控标签检测与会话绑定；逐 profile 注入。
7. **加密凭据库**：平台内加密存储，按会话短期取件，**运行时注入、不落盘**。
8. **运行位置**：厂商浏览器运行在用户本机 macOS / Windows；Go 服务端仅下发控制。
9. **目标平台**：Windows + macOS arm64。
10. **Profile 生命周期**：**每次会话临时新建**，用完清理。
11. **账号注入**：**运行时注入，不落盘**（密钥仅驻留节点代理内存）。
12. **自动化通道**：**优先用厂商内置 `/browser/*` 动作，能力不足再回退到 CDP**。
13. **版本策略**：**锁定内核/配置版本，手动灰度升级**。
14. **席位**：**公司统一采购，一人一席**。
15. **会话触发**：用户手动发起（非定时批量）。
16. **账号占用**：**账号独占**——同一站点账号同一时刻仅归一个会话。
17. **不可用环境处理**：不做置灰、不做排队；服务端**过滤掉被占用环境**，空列表显示"无可用环境"。
18. **前端**：复用现有 Next.js 做管理控制台。
19. **开放 API**：本期不做，仅控制台 + 节点面。

## 3. 架构总览

```text
                        ┌──────────────────────────────────────────────┐
                        │      控制面 Control Plane (本仓库, Go)        │
                        │  IAM(单租户, 多租户预留) · 环境库 · 凭据保险库   │
                        │  代理池 · 客户端记录 · 会话调度 · 审计/指标      │
                        │  Asynq: 代理体检/凭据轮换/会话回收/配置同步     │
                        └───────▲───────────────────────┬──────────────┘
              HTTPS/WSS(出站长连)│                       │  REST /api/v1
                                │                       │
        ┌───────────────────────┴───────┐      ┌────────┴─────────────────┐
        │  节点代理 (独立 Go 仓库)       │      │  管理控制台 (web/, Next)  │
        │  本地 API 客户端 + chromedp    │      │  环境/账号/代理/席位/会话  │
        │  ↓ 127.0.0.1:25325            │      │  复用 IAM/任务/审计/双主题 │
        │  Undetectable (Chromium 内核)  │      └──────────────────────────┘
        │  指纹+代理+cookie 于 profile   │
        └───────────────┬───────────────┘
                        │ 指纹在浏览器内核层生效；出站流量经指定代理
                        ▼
                 目标站点 / 代理出口网络
```

数据面流量由节点经代理直连出站，**不经过控制面**；控制面只承载控制信令与元数据。

## 4. 组件职责

### 4.1 控制面（本仓库）

复用现有能力并新增领域模块：

- **复用**：`internal/modules/iam`、`audit`、`task` + Asynq（`internal/platform/queue`、`scheduler`）、`database`、`httpserver`、`observability`。
- **新增领域模块**（领域包保持无适配器依赖）：
  - `environment`：环境定义（configid + overrides）、版本、发布自洽校验、厂商配置目录。
  - `credential`：凭据保险库（加密、轮换、授权、短期取件）。
  - `proxy`：代理资源、健康与风控标签、绑定与归还。
  - `device`：客户端记录、在线状态、能力上报、命令队列、席位/授权信息。
  - `session`：会话编排（原子分配 环境×代理×账号×客户端）、生命周期、回收。
- **新增平台适配器**：`internal/platform/kms`（信封加密主密钥抽象）、`internal/platform/controlchannel`（WebSocket 控制通道网关）。
- **多租户预留实现（不交付管理能力）**：新增最小 `tenant` 抽象（`internal/shared/tenant` 或 `internal/modules/tenant`），只提供 `ID` 类型、`Default` 常量、`WithTenant/FromContext` 与仓储过滤辅助函数；所有领域表带 `tenant_id`、所有仓储签名带租户维度，运行期由中间件注入默认租户。**全部预留点须以统一注释标记（见 §11.3）**。

### 4.2 节点代理（独立 Go 仓库，不在本仓库）

节点代理是平台把控制面指令落到用户机上的**唯一执行适配器**。它既是控制面的**出站客户端**，又是厂商浏览器的**唯一宿主进程**；但它**不是**控制面的一部分，也**不是**厂商浏览器的组成部分。

**一句话结论**：节点代理是**运行在终端用户自己的 Windows / macOS 机器上的常驻后台程序**，由**公司内部分发**（非公开商店），用户经**邀请注册 → 下载安装 → 登录同一账号 → 设备登记 → 就绪**的引导流程装好后，日常**不直接操作它**，所有业务交互都在管理控制台 web 完成。

#### 4.2.1 运行位置与形态

- **运行位置**：终端用户自己的机器（`windows/amd64`、`darwin/arm64`），**不是服务器侧组件**，不部署在控制面。控制面只与之建立 WSS 长连，不执行任何浏览器逻辑。
- **形态**：**用户级常驻后台程序 + 托盘/菜单栏图标**（状态、重连、日志、退出、检查更新）。**不做系统服务/守护进程**——厂商浏览器需要交互式桌面会话，且 profile 与席位是用户级。
- **每机一份**：一台机器一份节点代理；`devices` 表按 `machine_id` 记录，重复安装识别为同一设备。
- **前置依赖**：本机已安装**厂商浏览器**并登录有效**席位**（§4.3）。节点代理启动时检测，未就绪则阻断并给出引导，不进入长连。

#### 4.2.2 定位（是什么）

- **执行适配器 / Edge Executor**：把"下发一个环境"翻译为"用厂商本地 API 建 profile 并启动浏览器"。
- **控制面的出站客户端**：以用户账号登录，主动建立 WSS 长连，拉取命令与配置。
- **厂商本地 API 的唯一调用方**：仅它访问 `127.0.0.1:25325`。
- **凭据的运行时载体**：短期取件后在**内存**注入，用后即弃。

#### 4.2.3 边界（做什么 / 不做什么）

| 维度 | 节点代理负责 | 节点代理不负责（归控制面） |
|------|--------------|----------------------------|
| 业务决策 | 无 | 环境/代理/账号的分配、独占、配额、发布校验 |
| 身份与授权 | 用凭证登录、持有令牌 | 签发/校验令牌、RBAC、邀请与租户 |
| 真值源 | 无（只缓存配置快照） | 环境定义、厂商配置目录、凭据、代理池的唯一真值源 |
| 凭据 | 内存驻留、运行时注入、用后即弃 | 加密存储、轮换、短期取件令牌签发、审计脱敏 |
| 浏览器执行 | 建/启/停/删 profile、注入代理与账号、驱动页面 | 不参与浏览器实现；不修改厂商程序 |
| 数据面 | 页面流量经代理直连出站 | **不经控制面**，控制面不中转数据面 |
| 持久化 | 仅本地日志与最小状态；**不落盘凭据** | 全部业务数据落库 |

#### 4.2.4 职责清单

- 登录平台、建立并维持 WebSocket 长连（指数退避重连、补齐未确认命令）。
- 上报设备信息与厂商版本（OS、arch、agent 版本、厂商版本、内核版本、机器标识）。
- 接收并执行命令：创建/启动/停止/删除 profile、注入代理、运行时注入账号、会话释放与残留清理。
- 从节点面契约下载环境配置（configid + overrides + proxy）并据此建 profile。
- 上报命令回执、心跳与诊断日志。

#### 4.2.5 技术要点

- **技术**：Go；通过**厂商本地 REST API**（默认 `http://127.0.0.1:25325`）管理 profile，通过**厂商 `/browser/*` 动作**或 **CDP（chromedp）** 驱动页面；**不引入 Python**。
- **安全**：仅与 `127.0.0.1` 上的厂商 API 通信；账号密码**仅驻留内存**，注入后即弃。

#### 4.2.6 分发、安装与使用（用户如何拿到并跑起来）

**分发渠道（明确：不做公开上架）**

- **不走** App Store / Microsoft Store / 公开下载站；由**公司内部分发**，保证席位与授权可控、产物可签名。
- **入口在管理控制台**：登录后可见"下载客户端"页，按 OS/arch 给出对应安装包与校验值；邀请注册完成后引导至该页。
- **产物托管**：安装包放对象存储/CDN（静态产物）；控制面只提供**版本元数据与下载地址**（`GET /api/v1/nodes/releases`），**不承载安装包本体**。

**安装形态**

- **Windows**：签名安装器（MSI/EXE），用户级安装 + 开机自启（启动项/托盘常驻）。
- **macOS arm64**：签名 + 公证的 `.pkg`/`.dmg`，用户级 `LaunchAgent` 开机自启。
- 自动更新器随安装器一并安装（§4.2.7）。

**首次引导（onboarding，顺序固定）**

1. **前置**：安装**厂商浏览器**并登录有效**席位**（公司统一采购，§4.3）；节点代理检测未就绪则阻断。
2. 安装**节点代理** → 首次启动。
3. **登录**：使用与控制台**同一用户账号**（邀请注册所得，§7）；登录取得访问令牌。
4. **设备登记**：上报 `machine_id`、OS/arch、agent/厂商/内核版本 → 控制面生成 `devices` 行并归属该用户。
5. **席位/授权校验**通过 → 建立 WSS 长连，状态转"就绪"。
6. 之后用户**只在控制台 web 操作**（选环境、发起/结束会话），不直接操作节点代理。

**使用方式**

- 节点代理**没有面向用户的业务界面**，只有托盘/菜单栏状态项；业务操作全部在管理控制台完成。
- 常驻后台自动维持长连与会话执行；用户关闭托盘图标仅影响本机在线状态，不代表注销账号。

#### 4.2.7 更新与卸载

- **更新**：控制面按**兼容矩阵 + 灰度分组**下发 `update_agent` 命令与版本元数据；节点下载**签名包**、校验签名后原子替换并可回滚。用户也可在托盘手动"检查更新"。
- **厂商浏览器**：由厂商安装包升级；节点代理按"锁定版本、延后升级"策略**屏蔽/延后**厂商自动更新（§8.3），并上报 `vendor_version`/`core_version`。
- **卸载与设备移除**：卸载器清理自启项与残留；控制台可**吊销访问令牌并移除设备记录**；节点侧兜底清理残留临时 profile（§6.5、§9）。

#### 4.2.8 契约与耦合方式（本仓库与节点仓库的交界）

- **本仓库产出、节点仓库消费**：节点面 OpenAPI（`api/openapi.yaml` 的 `/api/v1/nodes/*` 部分）、命令信封 schema（§6.2）、配置文件 schema（§6.4）。
- **单一真值**：契约以本仓库为准；节点仓库不复制领域模型，只实现协议。
- **版本化**：节点上报 `agent_version` / `vendor_version` / `core_version`；控制面按**兼容矩阵**决定可下发命令与配置，避免节点升级不同步导致协议错配。
- **可共享的范围**：允许共享**生成的**契约客户端或小型协议常量包；**不共享**领域实现、数据库模型与业务逻辑，避免两个仓库形成隐式单体。

> 明确约束：节点代理源码、构建产物与更新逻辑**均不在本仓库**；本仓库 `AGENTS.md` 关于不得引入浏览器自动化运行时的禁令因此不被触碰。

#### 4.2.9 交付与运维责任边界

明确"谁构建、谁分发、谁运维"，避免安装与更新环节**无主**：

| 事项 | 本仓库（控制面） | 节点仓库 | 公司/运维 |
|------|------------------|----------|-----------|
| 节点代理源码与构建 | 不参与 | **负责** | — |
| 安装器 / 自动更新器 / 托盘 UI | 不参与 | **负责** | — |
| 代码签名与 macOS 公证 | 不参与 | 负责（使用公司证书） | **提供证书与公证账号** |

## 5. 领域模型与数据表（PostgreSQL）

> **首版按单租户运行、按多租户建模**：下表所有 `tenant_id` 列**从第一天就存在**，但运行期恒等于唯一"默认租户"（见 §11）。这样做的目的是把"多租户改造"从未来的**破坏性迁移**降级为**启用预留能力**——加约束、加过滤、加界面即可，无需改表结构。迁移策略见 §11。

## 6. 控制通道与下发协议

### 6.1 连接方向（关键约束）

用户机在 NAT 之后，**连接必须由客户端出站发起**。已确认采用：

- **WebSocket 长连**：节点代理连接 `wss://.../api/v1/nodes/connect`，携带**用户访问令牌**；服务端在其上推送命令帧。心跳用于在线判定；断线后指数退避重连并补齐未确认命令。

不实现长轮询降级。命令帧保持 HTTP/JSON 语义。

### 6.2 命令信封

```json
{
  "id": "cmd_...",
  "type": "provision_session",
  "session_id": "ses_...",
  "issued_at": "2026-09-22T10:00:00Z",
  "expires_at": "2026-09-22T10:02:00Z",
  "nonce": "base64",
  "payload": { },
  "signature": "ed25519:..."
}
```

命令类型（首期）：

- `provision_session`：下发环境（configid + overrides + 代理）+ 短期凭据取件令牌；节点创建并启动 profile。
- `stop_session`：停止并删除临时 profile。
- `rotate_proxy`：会话内换出口 IP。
- `update_agent`：触发签名更新。
- `collect_logs` / `probe`：诊断。

### 6.3 安全属性

- 身份：节点代理以**用户账号**登录取得访问令牌，长连走 WSS。
- 指令完整性：命令签名 + `nonce` + 短 TTL + 服务端单调计数。
- 传输：全程 HTTPS/WSS；生产强制 `COOKIE_SECURE=true` 与受信代理 CIDR。

### 6.4 配置与凭据交付

- **配置下载**：`GET /api/v1/nodes/environments/{revisionID}/config`，返回 `config_id + overrides + proxy`；节点代理据此经厂商 API 创建 profile。
- **凭据交付（已确认）**：**短期令牌取件 + 运行时注入**。控制面签发一次性、短 TTL 令牌；节点凭令牌取回凭据，**仅驻留内存**，通过厂商 `/browser/fill`（或 CDP）实时填入登录表单，随后丢弃。**不写入厂商 profile 的 accounts 字段，不落盘。**
- 明文凭据**禁止**进入日志、遥测、审计 payload。

### 6.5 本地 API 安全（强制要求）

- 厂商 API 必须配置为**仅监听 `127.0.0.1`**，并加主机防火墙规则；严禁绑定 LAN IP。
- 节点代理是唯一调用方；控制面**从不**直接访问厂商 API（也访问不到）。
- 设备丢失或重装时，吊销用户访问令牌并清理残留 profile。

## 7. 用户账号与客户端认证

- **用户主体**：凭邀请注册的用户是控制台与客户端的统一身份（`principal_type=user`）。
- **邀请制注册**：管理员生成邀请码/邀请链接 → 用户注册时提交 → 校验有效后创建 `users` 行；首版固定加入默认租户（`tenant_id = default`），不暴露租户选择。无邀请不可注册。
- **客户端认证**：节点代理用**同一用户账号**登录取得访问令牌，凭该令牌建立长连、下载配置、发起会话。
- **客户端记录**：登录时上报设备信息（OS、arch、agent 版本、厂商版本、内核版本、机器标识），控制面登记 `devices` 行并归属该用户；用于在线状态、席位可见性与遥测，非独立认证主体。
- **吊销**：禁用用户即吊销其客户端访问；用户可在控制台查看并注销自己的在线客户端。
- **两层账号概念**：用户对**平台**用自助注册账号；对**目标站点**由平台下发的站点账号自动登录，用户无感。二者无关。

## 8. 环境与指纹自洽

### 8.1 环境定义

一个环境 = `target_os + config_id（厂商配置）+ overrides_json + proxy_policy + 绑定账号`。

> **重要改写**：不再由控制面"生成指纹"。指纹数据由**厂商配置**提供，控制面只决定**用哪个配置、覆盖哪些维度**。

### 8.2 覆盖与自洽校验（发布前 checklist）

环境版本发布必须通过校验器，拒绝矛盾组合：

- `config_id` 必须存在于 `vendor_configs` 目录；
- `target_os` 与所选配置的 `os` 一致；
- **分辨率覆盖仅对 Windows 配置有效**，macOS 配置不得设置分辨率覆盖；
- **时区 / 语言 / 地理位置与代理出口地理一致**（由 `proxy_policy` 推导，写入 overrides）；
- UA 覆盖（若使用）不得与配置的 OS/平台冲突；
- 结果写入 `validated_at`，未通过不得发布。

### 8.3 版本与漂移控制（已确认）

- **锁定内核/配置版本，手动灰度升级**：在小范围机器先验证新内核/新配置对指纹表现的影响，通过后再铺开。
- 厂商自动更新可能改变指纹表现，因此需在节点代理屏蔽/延后厂商自动升级，并由平台记录每台机器的 `vendor_version`、`core_version`。
- 环境快照记录 `config_id` 与 overrides 的 `checksum`，保证可复现。

### 8.4 兼容性说明

- **Client Hints**：Chromium 内核原生支持，上一版 Firefox 分叉的 UA-CH 缺口**已消除**。
- **TLS/JA3**：由 Chromium 内核网络栈决定，仍无法任意定制；作为已知风险登记。
- **指纹自定义边界**：Canvas/WebGL 等无法单独设定，随厂商配置捆绑；如需特殊组合，只能挑选不同 `config_id`。

## 9. 会话生命周期

```text
requested → provisioning → active → releasing → released
                     └──────── failed / expired ────────┘
```

1. **用户发起**：用户在客户端下拉选择具体配置 → 经 WebSocket 长连到达控制面。**选择与确认的完整交互流程见 §9.1（部分待定）。**
2. **自动分配**：控制面**自动挑一个可用环境实例**（环境版本 + 其独占账号 + 可用出口 IP），在单事务内一并锁定；账号独占，被占用时该环境**不出现在可用列表**（见 §9.1）；分配时二次校验，被抢占则返回错误要求重选。
3. **下发**：创建 `session` 与 `provision_session` 命令 → 经 WebSocket 到达节点 → 节点经厂商 API **新建临时 profile**（configid + overrides + 代理）并启动。
4. **激活**：节点回执 + 心跳，会话转 `active`，代理与账号进入独占状态；节点凭短期令牌取回凭据并在内存中注入登录。
5. **释放**：用户关闭或 TTL 到期 → `stop_session` → 节点停止并**删除临时 profile**，代理归还并冷却，账号授权撤销。
6. **回收兜底**：Asynq 定时任务 `session.reap` 处理超时/失联会话；节点侧兜底清理残留 profile。

**独占性**：同一 `proxy` 与同一 `credential` 在同一时刻至多被一个活动会话占用。

### 9.1 环境选择与确认流程（部分定稿，其余待定）

> 状态：**第 3 项已定稿**，其余待定。任何"点下拉即自动完成"的说法都不成立。

1. **选择粒度与呈现（待定）**：下拉展示哪些字段、是否分组/搜索。
2. **是否二次确认（待定）**：选中即分配，还是先确认面板。取向 A 一键即用 / B 选择→确认→开始 / C 选择→预分配预览→确认。
   - 该取向决定 API 是否需要"预分配/确认"两接口，以及 `sessions` 是否需 `pending_confirmation` 态。
3. **不可用环境处理（已定稿）**：**不做置灰、不做排队**。服务端在可用环境列表中**直接过滤被占用项**，响应中不出现；前端只渲染返回值，空列表显示**"无可用环境"**（正常状态，非错误）。因过滤与分配存在时点差，**分配时仍须二次校验**。
4. **分配与就绪的反馈（待定）**：是否需要进度态与取消。
5. **失败与重试（待定）**：分配/下发/启动失败的呈现与重试。
6. **会话信息可见性（待定）**：环境名、代理地区、剩余时长、脱敏账号标识、结束入口。
7. **多会话并行（待定）**：是否允许同时多会话及配额约束。
8. **幂等与重连恢复（待定）**。

## 10. 代理池与质量管控

- **来源**：HTTP / SOCKS5（含认证）；住宅/移动优先，数据中心 IP 标注高风险。
- **体检 Worker（Asynq 周期任务）**：`proxy.healthcheck` 检测存活、延迟、真实出口 IP、属地真实性（与登记 geo 比对）、基础风控标签。
- **状态机**：`available → leased → cooldown → available`；连续失败进入 `quarantine`。
- **绑定**：出口 IP 与指纹地理强绑定；会话内 IP 不得变更（除非显式 `rotate_proxy`）。
- **注入**：由节点代理经厂商 API 的 profile `proxy` 字段或 `/proxies/add` 注入，格式如 `socks5://host:port:login:pass`。
- **泄露防护**：依赖厂商内核的 DNS/WebRTC 处理能力；环境校验中确认 WebRTC 覆盖与代理地理一致。

## 11. 多租户：首版单租户，多租户仅预留

**决策**：首版**不交付**多租户能力。不实现租户管理界面与端点、不做跨租户配额、不加租户维度 RBAC 判定、不做租户选择；运行期所有数据归属**唯一默认租户**。多租户作为**预留能力**，只保留**字段、接口与关键注释**。

这样做的收益：未来启用多租户时，是"打开开关 + 补过滤 + 补界面"，而不是"改表 + 改所有仓储签名 + 数据回填"的破坏性迁移。

### 11.1 预留内容清单

| 层 | 首版交付 | 预留（不交付，但留形） |
|----|----------|------------------------|
| 数据表 | 所有领域表带 `tenant_id`，默认租户单行 | 每租户唯一约束、租户级索引、租户配额字段 |
| 领域/仓储接口 | 仓储签名**带租户维度**，实现只按默认租户过滤 | 真正的多租户过滤与越权防护 |
| 请求上下文 | `WithTenant/FromContext`，中间件注入默认租户 | 从令牌/子域解析租户 |
| IAM | `users` 加可空 `tenant_id`，落默认租户 | 租户维度角色、跨租户管理员 |
| 邀请注册 | 邀请固定归属默认租户 | 邀请指定租户与角色 |
| API | 不提供 `/api/v1/tenants*` | 租户 CRUD、成员、配额 |
| 前端 | 无租户上下文与切换 | 租户切换、租户级页面 |

### 11.2 预留接口形态（示意，非最终签名）

```go
// internal/shared/tenant —— 最小预留抽象，无适配器依赖
type ID string

// Default 是首版唯一租户。启用多租户后此常量仅用于兼容与测试。
const Default ID = "default"

func WithTenant(ctx context.Context, id ID) context.Context
func FromContext(ctx context.Context) ID // 缺省返回 Default

// 仓储过滤辅助：所有领域查询经此构造租户条件，
// 首版恒等于默认租户，未来切换为真实租户即可。
func Filter(ctx context.Context) ID
```

中间件 `TenantScope`：从已认证主体解析租户，**首版无条件返回 `Default`**，并预留从令牌声明/子域解析的分支。

### 11.3 关键注释约定（强制）

所有预留点必须带统一标记，便于未来一次性检索与评估：

```go
// TENANT-RESERVED: 首版单租户，tenant_id 恒为 tenant.Default；
// 启用多租户时改为从上下文/令牌解析，并在此处补越权校验。
```

- 出现位置：领域仓储接口与实现、请求上下文注入点、`users`/邀请创建路径、所有新增领域表的迁移文件。
- 目的：让"预留"可被 `grep TENANT-RESERVED` 一次性盘点，避免遗漏导致未来越权。

### 11.4 迁移与启用路径（未来）

首版迁移只需：建 `tenants` 表 + 种入 `default` 行 → 各领域表加 `tenant_id`（默认 `default`）与非空约束 → 仓储签名带租户并透传默认值。字段已就位，**无需回填**。

未来启用多租户的分步路径：新增列/表可空 → 回填已有数据到默认租户 → 加非空约束与索引 → 打开中间件真实解析 → 补越权测试。RBAC 判定届时加入租户维度。

> 摘要：**字段、接口、注释就位；界面、端点、越权逻辑不交付。**

## 12. API 契约（`/api/v1` 扩展，仅设计）

**控制台/管理面**（JWT + RBAC）：

- `GET/POST /api/v1/environments`、`GET/PATCH /api/v1/environments/{id}`
- `POST /api/v1/environments/{id}/revisions`（发布，返回自洽校验结果）
- `GET /api/v1/vendor-configs`（厂商配置目录，管理员同步/查看）
- `GET/POST /api/v1/credentials`、`POST /api/v1/credentials/{id}/rotate`
- `GET/POST /api/v1/proxies`、`POST /api/v1/proxies/{id}/check`
- `GET /api/v1/devices`、`DELETE /api/v1/devices/{id}`
- `GET/POST /api/v1/sessions`、`POST /api/v1/sessions/{id}/release`
- `POST /api/v1/invitations`（管理员生成邀请；首版固定归属默认租户）
- `POST /api/v1/auth/register`（凭邀请码注册；首版加入默认租户）
- `GET /api/v1/client/downloads`（"下载客户端"页数据：按 OS/arch 的安装包版本与下载地址、校验值；**控制面不承载安装包本体**）
- `GET /api/v1/admin/client-releases`、`POST /api/v1/admin/client-releases`（管理员登记/发布节点代理版本，供兼容矩阵与灰度使用）

> **多租户预留（首版不实现）**：`GET /api/v1/tenants`、`/api/v1/tenants/{id}/members`、`/api/v1/tenants/{id}/invitations` 等租户管理端点**本期不交付**；`/auth/register` 的租户归属在首版固定为默认租户，接口预留可选 `tenant` 字段但不生效。

**节点面**（用户账号令牌认证）：

- `WS /api/v1/nodes/connect`（命令通道，携带用户访问令牌）
- `GET /api/v1/nodes/releases`（节点代理当前可用/推荐版本与下载地址，用于自更新）
- `GET /api/v1/nodes/environments/available`（该用户可见且**当前可分配**的具体配置；被占用项由服务端过滤；空 = 无可用环境）
- `GET /api/v1/nodes/environments/{revisionID}/config`
- `POST /api/v1/nodes/sessions`（用户发起会话，服务端自动分配）
- `POST /api/v1/nodes/credentials/{sessionID}/claim`（短期令牌取件）
- `POST /api/v1/nodes/heartbeat`、`POST /api/v1/nodes/commands/{id}/ack`

所有新增端点需同步进 `api/openapi.yaml` 并补齐契约测试。

## 14. 安全模型

- **身份**：控制台用户 JWT；节点代理以同一用户账号登录取得短期访问令牌，长连走 WSS。
- **指令完整性**：命令签名 + 短 TTL + nonce。
- **凭据保护**：信封加密（AES-256-GCM，AAD 绑定 tenant/environment/session），主密钥抽象为 `kms` 适配器；**短期取件 + 运行时注入 + 内存驻留 + 用后即焚**；不写入厂商 profile。
- **本地 API 加固**：厂商 API 仅绑 `127.0.0.1` + 主机防火墙；节点代理为唯一调用方。
- **审计**：复用 `audit` 模块，覆盖环境发布、凭据取用、代理分配、会话下发/释放、客户端登录/注销、席位变更；**审计不含凭据明文**。
- **供应链与合规**：厂商为客户闭源商业软件，席位授权合规由公司统一采购保证；节点代理产物签名校验。

## 15. 交付与部署

**本仓库（控制面）交付**

- 沿用现有 Dockerfile / Compose 与迁移流程；新增表走标准 migration。
- 提供"下载客户端"入口页与其数据接口（`/api/v1/client/downloads`）、节点代理版本登记/发布接口、兼容矩阵与灰度分组、`update_agent` 命令下发。**不承载安装包本体**。

**节点代理（独立仓库，见 §4.2.6–4.2.9）交付**

- Go 交叉编译 `windows/amd64`、`darwin/arm64`；打包**用户级安装器**（Windows MSI/EXE、macOS 签名+公证 `.pkg`/`.dmg`）；内置**签名自动更新器**与托盘 UI。
- **分发**：由**公司内部分发**（非公开商店）；产物推送到对象存储/CDN，控制面只引用版本元数据与地址。
- **安装与引导**：先装厂商浏览器并登录席位 → 装节点代理 → 登录同一用户账号 → 设备登记 → 就绪（§4.2.6）。

**厂商浏览器**

- 由厂商提供 Windows / macOS arm64 安装包；**公司统一采购席位**并分配；安装与激活纳入客户端引导流程（节点代理检测前置）。

**其他**

- **不再需要**：Linux 构建机、`multibuild.py` 交叉编译、Python 运行时打包。
- **联调**：需至少一台真实 Windows 与一台 macOS arm64 机器（WSL 无法运行厂商浏览器；控制面仍可在 WSL 开发）。

## 17. 分阶段路线图（设计视角）

- **P0 链路 PoC**：在单台 Windows/Mac 上验证「控制面下发 configid+overrides+proxy → 节点经本地 API 建临时 profile → 启动 → 注入账号 → 经代理打开站点」，确认指纹与地理自洽。**同时冻结节点面契约（OpenAPI + 命令信封 + 配置 schema）**，作为独立节点仓库的对接基线。
- **P1 用户准入与环境库（单租户）**：邀请制注册、客户端登录与记录、环境库与厂商配置同步、发布校验、单客户端下发。**数据模型带 `tenant_id` 但固定默认租户（§11）。**
- **P2 资源与生命周期**：代理池 + 体检、凭据保险库、会话原子分配与回收，**并定稿 §9.1 交互流程**（API、状态机、客户端交互）。
- **P3 控制台与治理**：完整管理台、席位列管、审计/指标、权限细化。
- **P4 交付硬化**：节点代理双端签名更新、厂商版本锁定与灰度机制、TLS/JA3 与指纹漂移专项验证。
- **P5 多租户启用（未来，非本期）**：打开租户中间件的真实解析、补租户维度 RBAC 与越权测试、租户管理与配额界面。

## 18. 风险与开放问题

| 风险 | 影响 | 应对 |
|------|------|------|
| 厂商锁定与闭源 | 受制于单一供应商与产品路线 | 环境模型与节点代理做隔离层，便于未来替换引擎 |
| 按席位持续付费 | 成本随用户数增长 | 公司统一采购、席位可见与回收 |
| **本地 API 无鉴权** | 同机/LAN 可起停 profile、读 cookie | 强制仅绑 127.0.0.1 + 主机防火墙；节点代理唯一调用方 |
| 内核/配置漂移 | 指纹表现随升级变化 | 锁定版本 + 手动灰度 + 记录 core_versions |
| 指纹自定义受限 | Canvas/WebGL 不可单独设 | 以选配 `config_id` 替代；环境校验保证自洽 |
| 临时 profile 每次重登 | 登录耗时、可能触发风控 | 评估引入 cookie 预热（仅 cookie，不含密码）；或按环境放宽为持久 profile |
| Chromium 内核 TLS/JA3 | 网络层指纹仍不可控 | 登记为已知风险，评估代理侧 TLS 方案 |
| 多租户改造 IAM 表 | 迁移与越权风险 | **首版即预留 `tenant_id` 与租户接口（§11）**，未来启用无需改表；届时再补领域层强制过滤与越权测试 |
| 节点代理与契约漂移 | 独立仓库升级不同步导致协议错配 | 契约以本仓库为唯一真值并版本化；节点上报版本，控制面按兼容矩阵下发 |
| 客户端分发与安装环节无主 | 用户拿不到/装不上、版本混乱 | 入口在控制台"下载客户端"，公司内部分发 + 签名/公证 + 自动更新 + 兼容矩阵灰度（§4.2.6–4.2.9） |
| 用户机前置未满足（无厂商浏览器/无席位） | 节点无法上号、体验断裂 | 节点启动即检测前置，未就绪阻断长连并给引导；席位状态在控制台可见 |
| 桌面运维面扩大（自启、更新、卸载） | 支持成本与安全面上升 | 用户级常驻 + 托盘最小 UI；令牌可吊销、设备可移除、卸载清残留；产物签名校验 |
| 凭据泄露面 | 高敏感 | 信封加密、短期取件、运行时注入内存驻留、审计脱敏 |

**待定事项（TBD）**：

**已确认决策（2026-09-22）**：

1. 指纹引擎：**Undetectable**（Chromium 内核），**全量替换 Camoufox**。
2. 控制通道：**WebSocket 长连**（客户端出站），不做长轮询。
3. 节点代理：**独立 Go 仓库**，厂商本地 API + 优先内置动作、必要时 CDP（chromedp）；不用 Python。
4. 厂商边界：**仅用本地执行器**，不用其云端 profile / 团队 / 用户功能；平台为唯一真值源。
5. 席位：**公司统一采购，一人一席**。
6. 环境/指纹：**厂商配置 configid + 有限覆盖**；控制面不再自研生成指纹。
7. 代理：**平台代理池，逐 profile 注入**（HTTP/SOCKS5 + 认证）。
8. Profile 生命周期：**每会话临时新建**，用完删除。
9. 账号注入：**运行时注入、不落盘**，密钥仅驻留节点内存。
10. 自动化通道：**优先厂商 `/browser/*` 动作，能力不足再回退 CDP**。
11. 版本策略：**锁定内核/配置版本，手动灰度升级**。
12. 目标平台：**Windows + macOS arm64**。
13. 用户准入：**邀请制注册**，客户端以同一用户账号认证。
14. 身份模型：**用户账号是唯一身份**；客户端只是机器记录。
15. 环境分配：**服务端自动分配可用环境**；用户下拉选**具体配置**。
16. 不可用环境：**服务端过滤，不做置灰/排队**，空列表显示"无可用环境"。
17. 账号占用：**独占**。
18. 会话触发：**用户手动发起**。
19. 开放 API：**本期不做**。
20. 本地 API 安全：**仅绑 127.0.0.1 + 防火墙**。
21. 多租户范围：**首版单租户**，多租户**仅预留**（字段、接口、注释），不交付界面/端点/越权逻辑（§11）。
22. 节点代理边界：**独立 Go 仓库**，本仓库只出契约与下载入口、不载其代码；节点为控制面出站客户端 + 厂商本地 API 唯一调用方 + 凭据运行时载体（§4.2）。
23. 节点代理运行位置：**用户自己的 Windows / macOS 机器**，用户级常驻托盘程序，非系统服务、非服务器组件（§4.2.1）。
24. 节点代理分发：**公司内部分发**（非公开商店），入口在管理控制台"下载客户端"；安装器签名/公证 + 托盘自动更新，控制面不承载安装包本体（§4.2.6）。
